Packaging info
--------------

https://python-packaging.readthedocs.io/en/latest/minimal.html

We don't necesarily create a subpackage folder for single module packages.


Namespace package style:
------------------------

- Native Python 3.3 namespace do not require anything. We aim 2.7 and 3.x, so we can't use them.

- pkgutil-style namespace packages are recommended,and are compatible with both Python 2 and 3::
    wtl/__init__.py => __path__ = __import__('pkgutil').extend_path(__path__, __name__)

- pkg_resources-style namespace packages are common but are **no longer recommended**::
    wtl/__init__.py => __path__ = __import__('pkg_resources').declare_namespace(__name__)

namespace issues: https://github.com/pypa/packaging.python.org/issues/265

Minimum struct:

wtl.mypkg: (complex sub-package)
  setup.py # Do not use namespace_packages=[...] parameters to setup()
  wtl
    + __init__.py # __path__ = __import__('pkgutil').extend_path(__path__, __name__)
    + mypkg
        + __init__ # for the mypkg
        + modules...

wtl.mypkg: (single module)
  setup.py # Do not use namespace_packages=[...] parameters to setup()
  wtl
    + __init__.py # __path__ = __import__('pkgutil').extend_path(__path__, __name__)
    mypkg.py


Version number
--------------

https://packaging.python.org/guides/single-sourcing-package-version/
https://stackoverflow.com/questions/458550/standard-way-to-embed-version-into-python-package

It seems ik to import __version__ from a module within the package, as long as that import does not cause the import of dependencies that are listed in install_requires.

This is the case with metrics.py, which uses standard libraries only. WOuld not work with something that uses, let's say, namespace. In which case we could put the version in a standalone _version.py file.

Supported formats (from https://pip.pypa.io/en/stable/reference/pip_install/)::

  Here are the supported forms:

  [-e] git://git.example.com/MyProject#egg=MyProject
  [-e] git+http://git.example.com/MyProject#egg=MyProject
  [-e] git+https://git.example.com/MyProject#egg=MyProject
  [-e] git+ssh://git.example.com/MyProject#egg=MyProject
  [-e] git+git://git.example.com/MyProject#egg=MyProject
  [-e] git+file:///home/user/projects/MyProject#egg=MyProject
  -e git+git@git.example.com:MyProject#egg=MyProject

  Passing branch names, a commit hash or a tag name is possible like so:

  [-e] git://git.example.com/MyProject.git@master#egg=MyProject
  [-e] git://git.example.com/MyProject.git@v1.0#egg=MyProject
  [-e] git://git.example.com/MyProject.git@da39a3ee5e6b4b0d3255bfef95601890afd80709#egg=MyProject

  git@bitbucket.org:<account_name>/<repo_name>.git

  or

  ssh://git@bitbucket.org/<account_name>/<repo_name>.git
